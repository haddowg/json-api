# A field builder carries the type its write hooks receive

The adapters check each written value's JSON type before hydrating it, so a hook typed `string` on a `Str` field is safe, yet `fillUsing()` and `deserializeUsing()` declared the value `mixed` and every author had to narrow it again. Each field builder now takes a covariant `TValue`, set by its `make()` to the type the check guarantees and widened through `@phpstan-self-out` by the calls that change what a write may carry: `nullable()`, `enum()` and `in()` over enum cases, and `deserializeUsing()`, which makes it `mixed`. The `onCreate()`, `onUpdate()` and `when()` scopes take the type of the builder their closure returns, and a closure that returns nothing makes the value `mixed` because PHPStan can't see what it declared. An `enum()`, an enum `in()` or a `deserializeUsing()` declared inside `onCreate()` or `onUpdate()` converts only that write's value, so the scoped type is exact: the case on the scoped write and the value as sent on the other, unless the field declares a conversion for it too. `when()` scopes validation only, so an enum declared there converts no write and a `deserializeUsing()` there runs on every write. Core puts each written number in its field's type before validation, a whole `5.0` an `int` where an `Integer` is declared and an `int` a `float` where a `Decimal` is, so an `Integer` takes `int` and a `Decimal` `float`. A `when()` condition's value stays `mixed` because validators ask it before the type check, and relations keep `mixed`. A builder carries its type from left to right, so a widening call written after the hook does not reach it. `tests/StaticAnalysis/HookValueTypes.php` holds each case, its refusals proved by ignores that fail the run once unmatched.
