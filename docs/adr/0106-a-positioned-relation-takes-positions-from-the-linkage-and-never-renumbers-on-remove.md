# A positioned relation takes positions from the linkage and never renumbers on remove

`positionedBy()` stores each member's position as an integer the server writes from the linkage: a replace writes indexes, an add appends after the highest position and a remove leaves gaps, because renumbering on every remove would rewrite rows the request never named, and gaps cost nothing when the field is only ever read as an order. The field is read-only to clients and becomes the default read order, so the linkage a client sends is the one way to change it. A pivot position is made read-only by the relation that owns the pivot, while a related type's position must be declared read-only there and is checked at warm-up, since a relation can't rewrite another resource's declaration without every resource being loaded to find the relations that point at it. Since positions are unique per owner in practice, core gives persisters a two-pass plan through temporary positions instead of leaving each adapter to discover the collision.
