# Every declared meta object is closed unless an entry opens it

A client generated from the OpenAPI document read a write's top-level `meta`, a resource object's `meta`, a pivot and identifier meta as open objects, so an idempotency key or a play count was untyped, and a mistyped pivot member was silently dropped. A type now declares a write's request `meta` per write in `requestDocumentMeta()`, its resource objects' `meta` in both directions in `resourceMeta()`, and an action's request `meta` per HTTP method, all with field builders, and every declared `meta` object, those and document, pivot and identifier meta, is closed unless one `AdditionalProperties` entry opens it, so each object follows one rule, adapters refuse an undeclared written member with a `422`, and `getMeta()` is deprecated in favour of an entry that renders the same output. A relationship write's meta-only document has its own `relationshipDocumentMeta()` rather than a widened `documentMeta()` parameter, because widening it would break every resource that overrides `documentMeta()`.
