# Every declared meta object is closed unless an entry opens it

A client generated from the OpenAPI document read a write's top-level `meta`, a resource object's `meta`, a pivot and identifier meta as open objects, so an idempotency key or a play count was untyped, and a mistyped pivot member was silently dropped. A type now declares a write's request `meta` per write in `requestDocumentMeta()`, its resource objects' `meta` in both directions in `resourceMeta()`, and an action's request `meta` per HTTP method, all with field builders, and every declared `meta` object, those and document, pivot and identifier meta, is closed unless one `AdditionalProperties` entry opens it, so each object follows one rule, adapters refuse an undeclared written member with a `422`, and `getMeta()` is deprecated in favour of an entry that renders the same output. Every response document's meta is declared in `documentMeta()`: `OperationType` gains cases for a relationship write's meta-only document and a write's `202` job document, so a `match` on the operation covers them. `documentMeta()` takes a second parameter, `?string $relation = null`, which core fills with the relation's name for the relationship cases and `null` otherwise, so a type can declare one relationship's document alone; the interface and `AbstractResource` declare it, so the call needs no suppressed check, and a released one-parameter override must add it.
