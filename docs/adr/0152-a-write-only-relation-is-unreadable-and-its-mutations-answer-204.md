# A write-only relation is unreadable, and its mutations answer 204

`writeOnly()` on a relation used to change nothing, so the relationship rendered with its linkage. It now mirrors a write-only attribute: absent from every response's `relationships`, unknown to `?include` (the `InclusionUnrecognized` a hidden relation gets), not countable, `404` on its related and relationship reads (refused by `Server` before the handler, since a host renders a related endpoint without consulting the parent's relation), and still writable through hydration and the relationship endpoint. A relationship mutation can't echo linkage it must not show, so `IdentifierResponse` renders `204`, which the spec allows when the result matches the request. The static `isIncludable()`/`isCountable()`/`exposesRelatedEndpoint()` report `false` for an unconditional write-only relation so a host's routes and metadata follow without new code; `writeOnly($when)` is judged per request and leaves those getters permissive.
