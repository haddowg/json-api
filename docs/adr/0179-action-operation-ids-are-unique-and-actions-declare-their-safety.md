# Action operation ids are unique, and an action declares its safety as `x-safety`

Consumers key on operation ids, and some flatten them into names such as tool names, but an action's id was `action.<type>.<path>` whatever its scope and methods. A type declaring one path at both scopes, or an action answering to two methods, gave two operations one id. So `ActionDeclarations` now rejects the same path at both scopes, a path that flattens to one of the type's operation-id words or relation names, and two action ids that differ only in case or punctuation. An action answering to several methods gets one id per method, `action.<type>.<path>.<method>`. A single-method action keeps the id it had. The words reserved are `fetchCollection`, `fetchOne`, `create`, `update`, `delete`, `fetchRelated`, `fetchRelationship`, `updateRelationship`, `addRelationship` and `removeRelationship`. The projector runs the check on every type, and an integration calls `ActionDeclarations::validate()` when it registers actions so a bad declaration fails at boot.

Whether an action reads or writes could only be guessed from its method, and a `POST` lookup reads like a write. Action metadata may now implement `DeclaresActionSafety` with three nullable flags. The projector stamps the declared ones, and only those, on the action's operation as `x-safety: {readOnly, destructive, idempotent}`. A single object keeps the flags together and follows the single-noun `x-generator` and `x-profile` names. CRUD operations get no stamp, because their method already says what they do. An action declared both read-only and destructive is rejected. `DeclaresActionExtensions` gives an action its own vendor extensions, merged over the type-wide set the way `operationExtensions()` is for a CRUD operation, and `x-safety` wins over an extension of the same name. Both are opt-in interfaces so existing metadata compiles unchanged, as with ADR 0150.

## Consequences

Each change is a scoped contract tier at 15 (`ACTION_METHOD_IDS`, `ACTION_SAFETY` and `ACTION_EXTENSIONS`), stamped only on a document that uses it. A document with a multi-method action has changed ids, so it is stamped too. Every other document keeps the baseline 13, byte for byte.

A type whose action shares a name with one of its relations, such as a `cover` download beside a `cover` relation, used to project and now fails. Renaming the action is the fix.
