# A rejected read-only attribute is a 403, and rejecting is opt-in per server

JSON:API lets a server either ignore a read-only member in a write body or reject the request, and core has always ignored it, so rejecting is a server-level opt-in that leaves the default alone. A refused attribute answers `403 ATTRIBUTE_WRITE_PROHIBITED` with a `/data/attributes/<name>` pointer, matching the `403` core already gives a prohibited relationship replacement: the body is well formed and the client is asking for something the server will not do, which is not the `422` of an invalid value or the `400` of a malformed document. The code is gated by its own `ErrorFeature`, read from an opt-in metadata interface, so a server that keeps ignoring such members projects the same document it did before.
