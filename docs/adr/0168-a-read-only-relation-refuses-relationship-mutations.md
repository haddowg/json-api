# A read-only relation refuses relationship mutations

`readOnly()` on a relation used to drop it from whole-resource writes only, so its `/relationships/{rel}` endpoint still replaced, added and removed. A relationship mutation is an update of the parent, so a relation read-only on update now fails `allowsReplaceFor`/`allowsAddFor`/`allowsRemoveFor` with the usual `403`s, and the static `allowsReplace()`/`allowsAdd()`/`allowsRemove()` report `false` when it is unconditional, which hosts already read for routes and the OpenAPI verbs. Folding it into the existing gates, rather than a separate check in `hydrateRelationship()`, means adapters that call those gates themselves inherit it; `readOnly($when)` is judged per request and leaves the static gates permissive, so the document keeps the superset.
