# A filter never matches through rows the caller cannot read

A filter that walks a relation, such as `WhereThrough`, answers yes or no about the rows at the other end, so matching through rows the caller cannot see leaks their values one probe at a time. Rows the related type's scope hides at any hop therefore don't exist for matching, and a hop the caller may not read at all refuses a client's filter with a `403` rather than quietly matching nothing, so a client can tell a forbidden filter from an empty result. A filter default is the author's choice rather than the client's, so it is never refused; it matches no row through a forbidden hop instead, which reveals nothing and leaves the endpoint working. Core lists the hops and asks the adapter's gate, so every adapter refuses the same filters.
