# A write must send the JSON:API Content-Type

`negotiate()` only policed the parameters of a JSON:API media type, so a write sent as `text/plain`, as a form, or with no `Content-Type` at all reached body parsing, and a framework that parses form bodies handed the fields on as if they were a document. `negotiate()` now takes `strictContentType`, which requires the header to be present and to be `application/vnd.api+json` with only `ext` or `profile`, and `ContentNegotiationMiddleware` applies it to every unsafe method. A `DELETE` with no body is the one exception: it is how a resource is deleted, clients send it without a `Content-Type`, and a browser cannot send it cross-origin without a preflight anyway. Strictness is a flag rather than the new default because `negotiate()` cannot tell a write from a read on its own, and an integration that drives it per route knows which of its routes take a document.

A raw-bodied custom action keeps skipping the JSON:API assertion and matches its body with `negotiateContentType()` instead. That refuses `text/plain`, `multipart/form-data` and `application/x-www-form-urlencoded` when they are reached only through a wildcard, because they are the media types a browser sends cross-origin without a preflight, so an action has to name them to take them.
