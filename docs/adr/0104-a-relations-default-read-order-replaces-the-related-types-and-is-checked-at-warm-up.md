# A relation's default read order replaces the related type's and is checked at warm-up

A to-many relation declares `defaultSort()` with the same directives a resource does, and for that relation it replaces the related type's default rather than being prepended to it, because the relation is the more specific scope, the same rule its `withSorts()` follows on a key clash. Its keys must name sorts the relation accepts, and since that vocabulary includes the related type's sorts, which a builder can't see, the full check runs in a validator a host calls at warm-up, beside `EagerLoadValidator`, while the builder rejects what it can see alone. Only the declared order is projected, as the `sort` parameter's standard `default`, so no generator contract tier is needed: a generator that ignores the keyword still builds a correct client, since the server applies the default either way.
