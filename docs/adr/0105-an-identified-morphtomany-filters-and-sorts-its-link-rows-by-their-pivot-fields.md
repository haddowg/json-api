# An identified MorphToMany filters and sorts its link rows by their pivot fields

An identified `MorphToMany` reads its members from link rows, and those rows can hold fields of their own, so it declares pivot fields with the `BelongsToMany` API and the same `meta.pivot` wire shape, and its relationship and related endpoints accept `sort` and `filter` over those fields only, run over the rows: they are the one vocabulary every member shares, whatever its type. This supersedes the consequence of ADR 0075 that a polymorphic relation's endpoints take no filter or sort parameters, for an identified `MorphToMany` alone; every other polymorphic relation still refuses both. The `identifiedBy()` closure returns each row beside its pair, so core reads pivot values without a store and its in-memory query is the reference adapters' link-row queries match, and an `identifierMeta()` resolver receives the member it renders, pair and row, which is what lets the two be combined at last.
