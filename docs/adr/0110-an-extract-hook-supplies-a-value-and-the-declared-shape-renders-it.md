# An extract hook supplies a value and the declared shape renders it

An `extractUsing()` or `computedUsing()` hook on an `Obj`, `Map`, `OneOf`, structured `ArrayList` or `Union` used to make the value author-shaped on a read: a closed object passed undeclared keys through and the read schema was an open object, so a code generator typed the read side as untyped while the write side of the same field was fully typed. Those hooks only say where the value comes from, so the value now renders through the declared shape exactly as a stored one does, and the read schema is the shape the field projects with no hook. Only `serializeUsing()`, which returns the finished wire value, still owns its shape and keeps the read schema open. This supersedes the read half of the consequence in [ADR 0088](0088-declared-objects-are-closed.md) for these two hooks.

## Consequences

An application whose extract hook returned keys its field does not declare loses them from responses, a declared child the hook leaves out renders `null` as it would from a column, and each child, member and element formats its own value. A field that needs to put an undeclared shape on the wire declares the extra members through `additionalProperties()` or moves the hook to `serializeUsing()`. The read schema of such a field tightens to closed, with every rendered child required, which uses no JSON Schema construct the documents did not already carry. The builder still refuses a hook on a list element or a union member: the hook belongs on the list or the union, and its value renders through the element or member from there.
