# An attribute's keys are selected through `fields` under a profile clients never send

A data table showing a few keys of one object attribute per row read the whole object for every row, so an open `Obj` or a `Map` can now declare `selectableKeys()`, a pattern, a predicate or both, and `fields[TYPE]=<attribute>.<key>` then selects one key, with the whole attribute winning when it is also listed, an unaccepted key being the existing `FIELDSET_MEMBER_UNRECOGNIZED`, and the value trimmed to the selection whether or not an `extractUsing()` hook used the `KeySelection` it receives. JSON:API 1.1 lists field names in `fields[TYPE]`, so a response that narrows applies the Field Selection profile and advertises it when the server registers it, without the client having to negotiate it, which keeps plain clients working and leaves an un-narrowed response unchanged. A separate query family and an `x-` extension on the OpenAPI parameter were rejected: the first duplicates what `fields` already means, and the second hides from generators what an `anyOf` of the member enum and one pattern per attribute states in standard keywords.
