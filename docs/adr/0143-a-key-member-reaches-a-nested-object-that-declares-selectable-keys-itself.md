# A nested fieldset reaches a nested object that declares one itself

A client showing one member of an embedded value object, such as the postcode or the latitude of an address, still received the whole object, so `fields[TYPE]` now takes `<attribute>.<key>.<key>` paths, splitting at every `.`, and accepts one only where each object along it is an `Obj` or a `Map` declaring `nestedFieldset()` that accepts the next key, reached through a declared child or an open object's member field. Nesting is opt-in per level, like the top level, so an author decides how far into a value a client may reach, and a list, an undeclared object or any other value still selects whole. A path selects nothing else of the objects it passes through, a key listed whole beside a path into it renders whole at every level, `NestedFieldset` carries a nested fieldset per narrowed key so a hook can load only those paths, and a closed `Obj` may now declare `nestedFieldset()`, since a typed address is the case this serves and a `Map`, whose keys are just as fixed, already could. The OpenAPI `anyOf` gains one pattern per path a nested fieldset may take in the same shape as the top-level ones, so the generator contract doesn't move.
