# A hook that receives the model takes it through a method template

An author types a hook's model parameter as the class, array or nullable type their provider loads, and both earlier declarations got in the way. `\Closure(mixed, …)` rejects any typed closure, since a closure taking `Track` cannot accept `mixed`, and `\Closure(never, …)` accepts every closure but PHPStan intersects the closure's own parameter type with `never`, so an `array` or nullable parameter reads as `never` in the body. A method-level `@template TModel` in the model position takes the closure's declared type unchanged. Parameters that carry the client's input, such as `deserializeUsing`'s value, the `when()` condition's value and `fillUsing`'s value, stay `mixed` because a typed closure there would throw on a malformed document. `tests/StaticAnalysis` is analysed with PHPStan's defaults by `phpstan-hooks.neon` to hold this.
