# A serializer override is narrowed by the keys its Resource declares

The OpenAPI document projects a type's nested fieldset members from its Resource class, so a type rendered by a serializer override advertised `fields[TYPE]=<attribute>.<key>` while the runtime answered a `400` or the whole attribute. Core now reads a nested fieldset member of such a type against the Resource the type was registered with, through the server's new `ProvidesResourcesInterface`, and trims the override's attribute value to the selection whatever it returns, so the request behaves as the document says without changing any override. An override that can load less implements `SerializesNestedFieldsetsInterface`, whose `getNestedFieldsetAttribute()` core calls in place of the attribute's callable with the `NestedFieldset`; a callable taking a fourth argument was rejected because nothing in the callable map's type would tell an author it is there. A bare serializer pair has no Resource and so no nested fieldset.
