# A sort reuses its field's description and its example is the default order

The `sort` parameter carried one fixed sentence and no example, so a client couldn't tell what a key orders by or what a sensible request looks like. A sortable field's sort, and a pivot field's, carry the field's description unless an explicit sort with the key replaces it, so authors write it once. Described keys follow `EnumDescriptionMode` exactly as enum values do, a markdown table in the parameter's description for renderers and an `x-sort-descriptions` map for generators, with a family's description in its `x-sort-families` entry rather than a key it could be mistaken for. The example is the order a request without `sort` already gets, the relation's and then the type's declared default, because that is the request most worth copying; without one it is the first exact key ascending, and a resource can name its own through `sortExample()`.
