# A nested date is stored as a UTC ISO string

A date child of an `Obj`, a `OneOf` variant or a structured `ArrayList` element lives inside one JSON value, and storing the `\DateTimeImmutable` it parses made a Doctrine `json` column or an Eloquent `array` cast write PHP's `{date, timezone_type, timezone}` dump, which only PHP reads back and which no JSON query or other client understands. So nested hydration stores a string: a `DateTime` child its instant in UTC as `Y-m-d\TH:i:s.uP`, one zone so stored values sort and compare as text, and a `Date` or `Time` child its value in the field's format with no zone conversion, since moving a calendar day or a time of day across zones changes it. A top-level date still hydrates the object, because an ORM maps that column as a date type, and a `fillUsing()` or `deserializeUsing()` hook still owns the value. The cost is that app code reading a nested date off the model gets a string, and a nested `DateTime` with no output zone renders in UTC rather than in the offset the client sent.
