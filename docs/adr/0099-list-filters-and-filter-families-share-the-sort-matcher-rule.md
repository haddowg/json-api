# List filters take a `[]` parameter and filter families share the sort families' matcher

A filter value that may contain commas needs the array form `filter[<key>][]=a&filter[<key>][]=b`, and OAS can't name a parameter whose name gains `[]` per member, so a filter declaring `acceptsList()` documents that form as its own `filter[<key>][]` parameter, an array with `style: form, explode: true` marked `x-filter-list`, beside the existing delimited `filter[<key>]` parameter only while the comma form is still accepted. We chose a second parameter over rewriting the delimited one because a set filter that never opts in must keep the document it has, and over a single `deepObject` because OAS leaves arrays in `deepObject` undefined. Filter families have no fixed keys, so they share one open `deepObject` `filter` parameter matched by `patternProperties` and listed under `x-filter-families`, and they resolve through the same exact-then-longest-prefix rule as sort families, now one internal matcher both `SortMatcher` and `FilterMatcher` call, with a resolved filter required to accept the list its family declares so the document and the data layer can't disagree.
