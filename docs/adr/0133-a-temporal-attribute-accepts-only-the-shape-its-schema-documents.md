# A temporal attribute accepts only the shape its schema documents

A `DateTime` documented as `format: date-time` used to hydrate anything PHP's date constructor reads, so `last year` or `2026-11-05 09:42` with no offset became a stored instant a client never meant, and a `fillUsing()` or `deserializeUsing()` hook received such strings unchecked. Every temporal field now takes a request string only in the shape its schema states: an RFC 3339 `date-time`, `date` or `time` when its format projects one, and otherwise exactly what its configured format writes. Anything else is `422 ATTRIBUTE_VALUE_INVALID` at the attribute, and the check runs before a hook too, which still receives the raw string. A `DateRange` bound is held to the `date-time` it documents the same way. We kept `DateTimeParser::parse()` lenient, because stored values and server-written cursors go through it and need not be RFC 3339, and gave adapters `DateTime::parseWire()` so a validator accepts exactly what the cast does.
