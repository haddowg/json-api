# A union holds one member per JSON type and projects one schema when that is exact

A `Union` takes at most one member per JSON type, an `Integer` and a `Decimal` counting as one, so a value's JSON type names the single member whose cast and constraints apply and whose PHP type comes back, with no discriminator and no first-match order to explain. That also makes a single schema exact: `type` lists the members' types and each member's keywords that only constrain its own type, such as `maxLength` or `minimum`, sit beside it. A member carrying a keyword that would constrain the other types too, such as `enum`, `const`, a `$ref` or a description, switches the projection to a `oneOf` of the members' schemas, with `null` as its own branch.

## Consequences

`ArrayList::element()` keeps returning only an `Obj` or `OneOf`, and a list of unions reports its union through `elementUnion()`, so an adapter that predates unions never receives a shape it cannot handle. A stored value no member takes is rendered unchanged, as a `OneOf` value selecting no variant is, rather than failing the response. Core makes every value-dependent choice for the data layers: `UnionValues` walks a write body and gives the pointer and selected member wherever a union's member applies, with whether a required union refuses that value as empty, and `ValueTypes::requiredRefusesEmpty()` answers the presence rule for every field, so the adapters agree without each re-deriving the rules. A data layer stores a union as its members' wire form through `Union::toStoredForm()`, never the hydrated value, since a top-level date member hydrates to an object a JSON column cannot hold, and reads it back with `fromStoredForm()` where its model wants the hydrated value. `requiredRefusesEmpty()` defaults to `true` and names the types that accept an empty-looking value, so a field core cannot type keeps the non-empty rule it had before.
