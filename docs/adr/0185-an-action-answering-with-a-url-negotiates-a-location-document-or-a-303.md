# An action answering with a URL negotiates a location document or a 303

An action that hands out a URL, such as a presigned download link, declares `SeeOther` with the media type the URL serves, `application/octet-stream` when that isn't known. A `303` alone serves a browser navigating to the action, but not a script: `fetch()` follows the redirect itself, and with `redirect: 'manual'` it gets an opaque response whose `Location` it cannot read. So when `Server::dispatch()` sees a `SeeOtherResponse` from such an action, it marks it, and the response answers a request preferring JSON:API with a `200` document carrying the URL as its top-level `location` link, and every other request with the `303`. A request prefers JSON:API only when its `Accept` names `application/vnd.api+json` and no other range it lists weighs more. An absent `Accept` and `*/*` get the `303`. That is the opposite of `AcceptNegotiator`'s tie-break for raw results (ADR 0173), on purpose: a client that sends nothing, or a link click, wants the file, while a JSON:API client always names its media type.

The declared media type is the opt-in. A bare `SeeOther` on an action, or one with only a description, stays the plain `303` at runtime and in the projection, as does a fetch's `SeeOther`, the async completion of ADR 0125. Existing actions such as an async completion redirect already have JSON:API clients that follow the `303`, and answering them `200` instead would break those clients in a minor release. For the same reason only an opted-in action has `AcceptNegotiator::negotiateAction()` return `null` rather than a `406` when nothing declared is acceptable. A bare `SeeOther` action may answer with a JSON:API body such as a `202`, so relaxing its `406` would send that body to a client that refused it.

The URL is a top-level `links.location`, with `type` from the handler or the declared media type and `meta.expiresAt` when it expires, because it is a link and JSON:API 1.1 lists the top-level links a document MAY carry without making the list exclusive. The vendored schema closes `topLevelLinks`, so `VendoredSchemaProvider` now opens it the way it opened `resourceLinks`: any other member must still be a valid link. A document needs a `meta`, `data` or `errors` member, so the location document carries a top-level `meta` with `expiresAt`, `null` when the URL does not expire. We chose that over `{}` or the action's description because it is always present, has one schema, and says something a client acts on. Both shapes carry `Cache-Control: no-store`, since the URL is short-lived and per caller, unless the handler sets its own.

## Consequences

An action's declared responses now reach core at runtime through `CustomActionOperation`'s optional `responds`. That is how dispatch knows the action opted in and which media type to render. An integration that doesn't pass them keeps the plain `303`.

The projection documents both responses for an opted-in action, through shared `LocationDocument` and `LocationLink` components. An action that also declares a `200` JSON:API body gets a `oneOf` of the two documents rather than a refusal, so existing declarations keep projecting. That is new structure, so it is a scoped contract tier, `ACTION_LOCATION = 17`, stamped only on a document whose actions declare `SeeOther` with a media type.
