# An action answering with a URL negotiates a location document or a 303

An action that hands out a URL, such as a presigned download link, declares `SeeOther`. A `303` alone serves a browser navigating to the action, but not a script: `fetch()` follows the redirect itself, and with `redirect: 'manual'` it gets an opaque response whose `Location` it cannot read. So when `Server::dispatch()` sees a `SeeOtherResponse` from a `CustomActionOperation`, it marks it, and the response answers a request preferring JSON:API with a `200` document carrying the URL as its top-level `location` link, and every other request with the `303`. A request prefers JSON:API only when its `Accept` names `application/vnd.api+json` and no other range it lists weighs more. An absent `Accept` and `*/*` get the `303`. That is the opposite of `AcceptNegotiator`'s tie-break for raw results (ADR 0173), on purpose: a client that sends nothing, or a link click, wants the file, while a JSON:API client always names its media type. A fetch's `SeeOther`, the async completion of ADR 0125, keeps the bare `303`.

The URL is a top-level `links.location`, with `type` from the handler or the declared media type and `meta.expiresAt` when it expires, because it is a link and JSON:API 1.1 lists the top-level links a document MAY carry without making the list exclusive. The vendored schema closes `topLevelLinks`, so `VendoredSchemaProvider` now opens it the way it opened `resourceLinks`: any other member must still be a valid link. A document needs a `meta`, `data` or `errors` member, so the location document carries a top-level `meta` with `expiresAt`, `null` when the URL does not expire. We chose that over `{}` or the action's description because it is always present, has one schema, and says something a client acts on. Both shapes carry `Cache-Control: no-store`, since the URL is short-lived and per caller, unless the handler sets its own.

## Consequences

An action's declared responses now reach core at runtime through `CustomActionOperation`'s optional `responds`, which is how dispatch knows the declared media type. An integration negotiates such an action with `AcceptNegotiator::negotiateAction()`, which returns `null` instead of a `406` when nothing declared is acceptable, because the action can still answer with its `303`.

The projection documents both responses, through shared `LocationDocument` and `LocationLink` components, and an action that also declares a `200` JSON:API body gets a `oneOf` of the two documents rather than a refusal, so existing declarations keep projecting. That is new structure, so it is a scoped contract tier, `ACTION_LOCATION = 17`, stamped only on a document whose actions declare `SeeOther`.
