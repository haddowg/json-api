# A one-of takes the keys any variant declares

A union rendered every member of its variant whether it was an attribute, a child or the items of a list, because only an `Obj` declared selectable keys. Each variant now opts in on its own `Obj`, given to `variant()` as the one `Obj` named for it or returned from `variants()`, rather than through a method on the union's builder naming the variant, so a variant declares its keys where it declares its fields. A key is accepted when one variant accepts it, a path keeps going inside the variants that accept it, and the OpenAPI `anyOf` gains the union of the variants' paths wherever the union sits, so the generator contract doesn't move. Each value renders the selected keys its own variant accepts and nothing more, the same as an `Obj` missing a selected member, rather than rendering a variant that never opted in whole, which would hand a client members it never asked for. The discriminator always renders, and a hook's selection holds it, because a client reading a narrowed value needs to know which variant the rest belongs to; an undiscriminated value accepting none of the keys renders as `{}`.
