# A pivot segment reaches the pivot row of the relation before it

`WhereThrough` paths could start at a pivot row, `pivot.<relation>.<field>`, and `->through()` had no such form, so `WhereThrough` couldn't be deprecated without losing filters. A `pivot` segment in a `->through()` path now reaches the pivot rows of the relation before it, or of the relation the filter or sort runs under when it leads, and a pivot row is gated by that relation's read permission since it has no type of its own. Core can't read what a pivot row links to from any declaration, so a hop past `pivot` walks a relation the data layer names through `PivotRowRelations`, and the reached type's scope, gate and encoder apply from there; a sort takes only a leading `pivot`, the one pivot row each member has, because anywhere else the segment follows a to-many.
