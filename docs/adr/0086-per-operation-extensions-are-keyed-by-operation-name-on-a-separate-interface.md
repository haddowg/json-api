# Per-operation extensions are keyed by operation name on a separate interface

`DeclaresOperationExtensions::operationExtensions()` takes an `OperationType`, so it can only reach the five CRUD operations, and a feature-gated relation had no way to tag just its related or relationship endpoint. Widening that method's parameter would break every hand-written implementation, so the per-operation set lives on a new opt-in `DeclaresNamedOperationExtensions` whose map is keyed by the operation names `operationExamples()` and `operationScopes()` already use, which an integration fills straight from an array in its configuration. The layers merge type-wide, then CRUD, then named, then an action's own, and an unexposed name fails the projection the way an unexposed example name does. Actions are left out of the map because `DeclaresActionExtensions` already covers them.
