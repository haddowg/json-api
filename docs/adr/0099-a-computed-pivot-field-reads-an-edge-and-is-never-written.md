# A computed pivot field has no column, and every pivot hook reads an edge instead of the join row

A pivot field without a column, from `computed()` or `computedUsing()`, is computed: it is left out of `writablePivotFields()` and the request pivot shape even when not declared read-only, since there is nowhere to write it, and a relation with no stored pivot field needs no association entity, so an adapter can serve it over a plain join table. An `extractUsing()` hook on a stored field changes only how it is read, as on an attribute, so the field stays writable to its column. Every pivot hook receives a `PivotEdge` of the parent, the related member and the link's stored values rather than the join row, because the row is a Doctrine entity on one adapter and an Eloquent pivot model on another, and a computed field may have no row at all.
