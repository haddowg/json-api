# A cursor page counts its collection when a client asks

A countable collection paged by cursor accepted `?withCount=_self_` and answered without `meta.total`, because the cursor branch of the `WindowExecutor` could not count and both adapters left a cursor paginator out of the count decision. Paging by cursor still never needs a total, but a client that asks for the collection's size is asking about the collection, not the page, so `runCursor()` now takes an optional count closure and the `CursorCollectionResult` carries its result. The count covers the filtered and scoped collection and ignores the cursor bounds and the page size. It renders only as the top-level `meta.total`: a cursor page keeps no `meta.page.total` and no `last` link, since neither has a meaning without page numbers. This replaces the "always count-free" consequence of [ADR 0025](0025-collection-windowing-and-keyset-execution-live-in-core.md); a cursor paginator still has no `withCount()` author opt-in.
