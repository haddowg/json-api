# A method the path does not accept is a 405 the adapter raises, catalogued on opt-in

A request whose path exists but whose method no route takes, such as a write to a read-only type, never reaches core, so the adapters left it to their framework, which answered with an HTML page on an API that otherwise speaks only JSON:API. Core now ships `MethodNotAllowed`, a described `405 METHOD_NOT_ALLOWED` carrying the HTTP-mandated `Allow` header through `CarriesResponseHeadersInterface`, for an adapter to raise from its router's failure. Only an adapter that owns routing can raise it, so its code is gated by its own `ErrorFeature`, read from the opt-in `DeclaresMethodNotAllowed` metadata interface like `ATTRIBUTE_WRITE_PROHIBITED`. A server whose metadata does not opt in projects the same document it did before, and the contract witness and baseline do not move. No operation documents a `405` response, because an operation is one method on one path and the error is about the others.
