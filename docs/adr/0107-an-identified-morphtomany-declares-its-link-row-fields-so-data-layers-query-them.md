# An identified MorphToMany declares its link-row fields so data layers query them

The `identifiedBy()` closure maps a parent to every pair at once, so an adapter paging link rows in SQL had to rebuild each row's pair by running the closure over a doctored parent, and fell back to memory whenever a scope hid rows of a member type. `identifiedByRows()` instead declares the row class through `through()` and the row's owner, type and id fields, with an explicit map from stored type to JSON:API type that core never infers, and core derives the members from the rows and sets the rules every data layer runs: a row counts when its type maps to a declared type and it has an id, a narrowed type counts only its admitted ids before the page is cut, and ties break by stored type then id. The fields are fields of the row, not columns, so they mean the same to a Doctrine entity and an Eloquent model, and the closure stays for storage they can't describe, served in memory by `InMemoryLinkRows`, which applies the same rules and so remains the witness adapters are checked against.
